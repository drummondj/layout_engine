# Regenerate the database from schema.py

`src/database/schema.py` is the only hand-edited source for everything under
`src/database/generated/`. Never edit files in `generated/` directly — re-run
codegen instead.

Generated by this project's own `codegen` fork (a project-specific fork of
the external [cmg](https://github.com/johndru-astrophysics/cmg) tool,
checked out at the repo root as `codegen/`) — not upstream cmg, which
stays generic/reusable. `schema.py` imports `from codegen.schema import ...`
accordingly. The fork owns this project's own display/formatting
conventions (e.g. `dbu`-typed fields, LEF/DEF unit conversion) that don't
belong in the general-purpose upstream tool — see `codegen/codegen/schema.py`'s
`TYPEMAP` and `Field.wrap_with_to_property*` methods before adding a new
field type.

## Steps

1. **Bump the schema version.** Every change to a class or field requires
   incrementing `version=` in the `Schema(...)` call at the top of
   `src/database/schema.py` — codegen embeds this so old serialized databases
   are rejected instead of silently misread. (A pure formatting/codegen-side
   change with no schema field/class shape change doesn't need this — e.g.
   renaming a field's `type=` alias without changing its generated C++ type.)

2. **Ensure the local `codegen` fork is installed, editable** (paths
   below are relative to the repo root - the directory holding `codegen/`
   and `backend/`):

   ```
   pip install --user -e codegen      # or: cd codegen && poetry install
   python3 -c "import codegen; print(codegen.__file__)"
   ```

   The second line must print this checkout's `codegen/codegen/__init__.py`.
   A non-editable install (`pip install codegen` without `-e`) is a frozen
   copy that silently goes stale as `codegen/` changes. If pip refuses with
   "externally-managed-environment", add `--break-system-packages` (a
   `--user` install doesn't touch the system packages) or use poetry.

3. **Run the generator** - the command is `codegen` (it was `cmg`, the
   upstream tool's name, until NEW_FEATURES_SEPT_2026.md item 26 renamed it
   so it can't collide with an installed upstream `cmg`). INDEXED_POOLS is
   the fork's only export style, no `--export-style` flag needed:

   ```
   codegen --schema backend/src/database/schema.py --output backend/src/database/generated
   ```

   (`poetry run codegen ...` from inside `codegen/` if you installed with
   poetry - adjust the relative paths to `../backend/...`.)

4. **Diff the output.** `generated/` is `.gitignore`d, so `git diff` won't
   show anything — `git status`/`git diff` can't be used to spot unexpected
   churn here. Copy the directory aside (e.g. to a scratch location) before
   regenerating if you need a real diff baseline; otherwise the generator
   deletes and fully recreates the output directory on every run, so a
   stale/orphaned file (e.g. from a since-renamed class) can't survive a run
   even without diffing.

5. **Rebuild and run tests** once a build exists (see the `build-test`
   skill) to confirm the regenerated code still compiles and passes.
